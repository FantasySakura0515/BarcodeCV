# Web 前端 zh-TW 在地化規格

## 目標與範圍
- 將前端產品化後的使用者介面文案統一為繁體中文（zh-TW）。
- 僅調整前端可見文字（導覽、標題、說明、按鈕、空狀態、載入/錯誤訊息、表格欄位、狀態文字）。
- 不變更功能邏輯、資料結構、API 介面與契約。

## 文案語氣
- 風格：專業、中性、精簡。
- 句型：優先短句，避免口語與情緒化詞彙。
- 視覺一致性：同類操作用語固定（例如「執行辨識」「重新掃描鏡頭」「擷取並存檔辨識」）。

## 名詞與術語對照（Glossary）
| 英文術語 | zh-TW 標準用語 | 規則 |
|---|---|---|
| Dashboard | 儀表板 | 導覽與頁面標題統一使用 |
| Image Detection | 影像辨識 | 指單張檔案辨識流程 |
| Live Detection | 即時辨識 | 指連續掃描/預覽流程 |
| Batch Records | 批次紀錄 | 批次歷史查詢頁 |
| Model / Models | 模型 | 單複數皆以「模型」呈現 |
| Run ID (RID) | 批次 ID（RID） | 顯示中文 + 英文縮寫 |
| Object ID (BID) | 物件 ID（BID） | 顯示中文 + 英文縮寫 |
| Barcode | 條碼 | 固定使用「條碼」 |
| Data Matrix | Data Matrix | 保留英文專有名詞 |
| OCR Text | OCR 文字 | OCR 保留英文縮寫 |
| Confidence | 信心分數 | 百分比顯示 |
| Active / Inactive | 啟用中 / 未啟用 | 狀態徽章統一 |
| Retry | 重試 | 錯誤區塊與操作按鈕統一 |
| Export | 匯出 | 功能按鈕統一 |

## 一致性規則
1. ID 欄位統一格式：`中文名稱（英文縮寫）`，例如「批次 ID（RID）」。
2. 技術名詞保留原文時，以中文主詞 + 英文補充或縮寫（必要時使用括號）。
3. 狀態文案統一：
   - 可用/不可用
   - 啟用中/未啟用
   - 執行中/待命
4. 空狀態與錯誤訊息採「問題 + 建議動作」結構。

## 混合語言與例外
- 預設禁止中英混用。
- 以下可保留英文：
  - 專有技術名詞或標準縮寫（OCR、RID、BID、OpenCV、API、Data Matrix）。
  - 模型框架與版本字串（例如 `opencv · v1.0.0`）。

## Fallback 規則
1. 若後端直接回傳錯誤 detail（未知語系），前端仍顯示原文 detail，但外層提示維持 zh-TW（例如「辨識失敗：{detail}」）。
2. 若欄位值缺失：
   - 條碼：`未偵測到`
   - OCR：`無` 或 `沒有 OCR 文字。`
   - 備註：`無備註`
3. 若清單為空：使用對應空狀態文案，不顯示英文預設字串。

## 驗收標準
- 目標頁面與共用元件不出現未翻譯英文 UI 文案。
- 主要術語在所有頁面一致。
- `npm run lint` 與 `npm run build` 皆通過。
